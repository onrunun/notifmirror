# NotifMirror — Android ↔ macOS bridge

[![CI](https://github.com/onrunun/notifmirror/actions/workflows/ci.yml/badge.svg)](https://github.com/onrunun/notifmirror/actions/workflows/ci.yml)

See your Android notifications on your Mac, reply from your keyboard, sync
your clipboard, control your media, and move files between both — all over
local Wi-Fi. Single-user, LAN-only: no cloud relay, no accounts, no data
leaving your network.

## Features

| | |
|---|---|
| **Notifications on your Mac** | Every notification from your Android phone appears as a macOS banner — app icon, title, and body included. WhatsApp-style inline photos work too. |
| **Reply from your Mac** | Hover a banner and hit **Reply** to answer a message with your keyboard. The reply is sent from your phone, so it shows up as sent from you. |
| **Sync'd dismissal** | Swipe a banner away on the Mac and it disappears on your phone, and the other way around. |
| **Clipboard sync** | Copy on the Mac, paste on the phone — and copy on the phone, paste on the Mac. Opt-in and off by default, since clipboards often hold passwords and 2FA codes. |
| **Media controls** | Now-playing, album art, and play/pause/next/prev right in your Mac menu bar, driven by whatever's playing on your phone. |
| **Send files, both ways** | Pick a file on the Mac → it lands in the phone's Downloads. Share a photo or PDF from Android → it lands in `~/Downloads` on the Mac. |
| **Browse the phone's files** | A **Files** pane lists your phone's storage. Works over Wi-Fi (with Android's "All files" permission) or — usually faster — over adb. |
| **Screen mirroring** *(optional, developer-only)* | A **Mirror screen** menu item shows your phone on the Mac via [scrcpy](https://github.com/Genymobile/scrcpy). Requires adb; see [setup](#optional-screen-mirroring-developer-only). |

## Quick start

```sh
./scripts/build-and-deploy.sh   # builds Android + Mac, installs both, opens the Mac app
```

First launch: NotifMirror opens a **Pair** window with a QR code. Open the
NotifMirror app on your phone, grant Notification Access, and scan the code —
that's it. Everything else runs in the Mac menu bar. Full steps below.

## Architecture

- **Mac**: SwiftUI menu bar app (`LSUIElement`) hosting a `NWListener` WebSocket
  server that also advertises `_andnotif._tcp` via Bonjour.
- **Phone**: Kotlin app whose `NotificationListenerService` extracts payloads
  and forwards them through an OkHttp WebSocket client. The client lives in a
  `specialUse` foreground service and keeps the WS alive across Doze/Wi-Fi
  flaps.
- **Protocol**: see [`protocol/PROTOCOL.md`](protocol/PROTOCOL.md).

```
[Phone] NotificationListener → OkHttp WS  ==  Wi-Fi  ==  NWListener WS → UNUserNotificationCenter [Mac]
```

## Prerequisites

- macOS 14+ with Xcode 26+ (the macOS 26 SDK is required to build —
  `SelfSignedCert` uses `SecIdentityCreate`, which older SDKs don't declare).
  Xcode ad-hoc signing is fine.
- [`xcodegen`](https://github.com/yonaskolb/XcodeGen): `brew install xcodegen`.
- JDK 17+. Android Studio ships a JBR 21 at
  `/Applications/Android Studio.app/Contents/jbr/Contents/Home`. Set `JAVA_HOME`
  to it (or any JDK 17+); `scripts/build-and-deploy.sh` falls back to the
  Android Studio JBR automatically when `JAVA_HOME` is unset.
- Android SDK at `~/Library/Android/sdk` (or update `android/local.properties`).

## One-shot build & deploy

[`scripts/build-and-deploy.sh`](scripts/build-and-deploy.sh) builds both apps,
installs the debug APK onto any connected Android device (and launches it),
and copies `NotifMirror.app` into `/Applications` before opening it.

```sh
./scripts/build-and-deploy.sh              # android + mac in parallel
./scripts/build-and-deploy.sh android      # android only (gradle + adb)
./scripts/build-and-deploy.sh mac          # mac only (xcodebuild + /Applications)
./scripts/build-and-deploy.sh --sequential # both, one after the other
```

Requirements: `adb` with a device visible to `adb devices` (USB or wireless
debugging paired), `xcodebuild`, and `xcodegen` if you want `project.yml`
regenerated on every run. The mac build uses ad-hoc signing (`CODE_SIGN_IDENTITY="-"`).
If `/Applications` isn't writable the script falls back to `sudo ditto`.

For the individual manual flows, see the two sections below.

## Build & run the Mac app

```sh
cd mac
xcodegen generate
xcodebuild -project NotifMirror.xcodeproj -scheme NotifMirror \
  -configuration Debug build \
  CODE_SIGN_IDENTITY="-" CODE_SIGNING_REQUIRED=NO
```

Or open `mac/NotifMirror.xcodeproj` in Xcode and press ⌘R.

On first launch NotifMirror will:

1. Generate a random 256-bit pairing secret and store it in the login Keychain.
2. Start listening on a random port and advertise `_andnotif._tcp` via Bonjour.
3. Open the **Pair** window with a QR code containing host/port/secret/name.

Menu-bar commands: show pairing QR, regenerate secret, quit.

## Build & install the Android app

```sh
cd android
./gradlew :app:assembleDebug
~/Library/Android/sdk/platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk
```

For **wireless debugging** (phone on the same Wi-Fi):

1. On the phone: Settings → Developer options → Wireless debugging → enable.
2. Tap *Pair device with pairing code*; note the shown `IP:PORT` and 6-digit code.
3. On the Mac:
   ```sh
   ~/Library/Android/sdk/platform-tools/adb pair <IP>:<PAIRING_PORT>
   # enter 6-digit code
   ~/Library/Android/sdk/platform-tools/adb connect <IP>:<DEBUG_PORT>
   ```

After install, open **NotifMirror** on the phone and:

1. Grant **Notification Access** (button opens the system screen).
2. Grant POST_NOTIFICATIONS and (optional) ignore-battery-optimizations.
3. Tap **Pair**, scan the QR from the Mac.
4. Tap **Start service** if it hasn't auto-started.

## Verify end-to-end

1. Send a Telegram / WhatsApp message → Mac banner.
2. Swipe the banner away on Mac → notification disappears on phone.
3. Hover the banner → **Reply** → type → Enter → message is sent on phone.
4. Put phone in airplane mode for 15 s → reconnect should be automatic.
5. Reboot phone → boot receiver restarts the foreground service.
6. **Clipboard**: copy text on Mac → paste on phone. Open the NotifMirror app
   on the phone, copy text → paste on Mac. (Background-copy on Android
   doesn't cross; that's an OS restriction, not a bug.)
7. **Media**: start Spotify / YouTube Music on phone → Mac menu bar shows
   title, artist, and play/pause/next/prev buttons.
8. **Files (Mac → Android)**: menu bar → "Send File to Phone…" → pick a
   file → check the phone's Downloads folder.
9. **Files (Android → Mac)**: share any file (photo, PDF) from another app →
   pick NotifMirror → check `~/Downloads` on Mac.

## Optional: screen mirroring (developer-only)

NotifMirror itself does **not** stream video. The "Mirror screen" button in
the menu bar just launches [scrcpy](https://github.com/Genymobile/scrcpy) and
hands it the connected device. That means this feature is only useful if
you're the kind of person who's willing to turn on Developer options and run
adb commands — regular users can ignore it.

**1. Install scrcpy and adb on Mac.**

```sh
brew install --cask android-platform-tools    # gives you `adb`
brew install scrcpy
```

**2. Turn on Developer options on the phone.**

Settings → About phone → tap **Build number** seven times until the phone
confirms "You are now a developer." Then under Settings → System → Developer
options, enable one of:

- **USB debugging** — if you plan to plug the phone into the Mac with a cable.
- **Wireless debugging** — on Android 11+, this is the no-cable path.

**3. Pair the phone with adb.**

USB cable path — connect the cable, tap *Allow USB debugging* on the phone's
"Allow USB debugging?" prompt (check *Always allow from this computer*), then:

```sh
adb devices    # expect one line showing your device serial
```

Wireless debugging path (Android 11+) — on the phone:

1. Settings → Developer options → Wireless debugging → **On**.
2. Tap *Pair device with pairing code*. The phone shows `IP:PAIRING_PORT` and
   a six-digit code.
3. On the Mac, in the same Wi-Fi network:
   ```sh
   adb pair <IP>:<PAIRING_PORT>            # paste the six-digit code when asked
   adb connect <IP>:<DEBUG_PORT>           # the separate "IP & port" shown on the Wireless debugging screen
   adb devices                             # should now list the phone
   ```

**4. Launch screen mirroring from NotifMirror.**

With `adb devices` showing your phone, open the NotifMirror menu bar →
**Mirror screen**. A window opens showing the phone; close it to stop
scrcpy.

Note: if the menu entry can't find `scrcpy` or `adb` on `PATH`, quit
NotifMirror, run it once from a terminal (`open /Applications/NotifMirror.app`)
so it inherits your shell PATH, or move the binaries into `/opt/homebrew/bin`
(the default Homebrew location).

## Security model

- Notifications, clipboard text, and file bytes travel over a **plaintext
  WebSocket** + a 256-bit shared secret sent in `hello`. The threat model is
  a trusted personal LAN.
- A passive sniffer on the same Wi-Fi can read notification content,
  clipboard text, and file bytes in plaintext. If that matters, upgrade to
  TLS with a self-signed cert whose SHA-256 fingerprint is embedded in the QR
  payload (the protocol reserves a `fp` field).
- **Clipboard Sync is opt-in** and off by default — enable it in the Mac
  menu bar when you're ready. Clipboards often hold passwords / 2FA codes.

## Troubleshooting

- **Mac banner never appears**: confirm Notification Access is on for
  NotifMirror (System Settings → Notifications → NotifMirror). Check the
  Mac console for `WsServer listening on port …`.
- **Phone never connects**: Mac firewall may be blocking incoming WS. Allow
  `NotifMirror.app` in System Settings → Network → Firewall. Fall back to the
  QR host/port if mDNS isn't working.
- **Reply doesn't send on WhatsApp**: some messengers ignore replies without
  `RemoteInput.setResultsSource(SOURCE_FREE_FORM_INPUT)` — we set it, but if
  an OEM clone of WhatsApp misbehaves, check logcat for `MirrorListener: reply`.
- **Foreground service killed**: grant *Unrestricted* battery usage and the
  ignore-battery-optimizations permission.

## Development

### Tests

Both codecs are covered by mirrored round-trip suites, so a protocol change
on one platform fails CI on the other.

- **Android (JVM, no emulator needed):**
  `cd android && ./gradlew :app:testDebugUnitTest`
- **macOS (XCTest):**
  `cd mac && xcodegen generate && xcodebuild -project NotifMirror.xcodeproj -scheme NotifMirror -destination 'platform=macOS' -derivedDataPath build/DerivedData CODE_SIGN_IDENTITY="-" CODE_SIGN_STYLE=Manual test`

### Lint & format

- **SwiftLint**: `cd mac && swiftlint lint --config .swiftlint.yml`
- **Detekt** (Kotlin): `cd android && ./gradlew detekt`
- **Android Lint**: `cd android && ./gradlew :app:lintDebug`
- `.editorconfig` at the repo root covers editor-level formatting.

`./scripts/build-and-deploy.sh` doesn't run these; CI does, on every push/PR.

### Versioning & releases

Both apps share one version. Bump it once:

```sh
./scripts/bump-version.sh 1.1.0          # updates both apps + CHANGELOG, tags v1.1.0
git push --follow-tags                   # CI drafts a GitHub Release with the APK + macOS bundle
```

Releases are tagged `v<semver>`; see [`CHANGELOG.md`](CHANGELOG.md).
Dependencies are updated automatically by Dependabot (weekly).
